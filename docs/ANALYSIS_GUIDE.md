# Контекст для анализа данных (прочитать первым)

Документ для ИИ-модели, которая анализирует данные домашней резервной энергосистемы. Цель — понять данные без
лишних вопросов. Всё время — местное время приставки.

## Система (заполните под свою установку)

- Назначение: резервное питание дома / ИБП (частые отключения сети). Солнечные панели: <есть/нет> (если нет, поля PV
  всегда ≈0, а контроллер пишет «напряжение панелей низкое» — это норма).
- **Инвертор Must <модель>** (серия PV1800), <мощность> кВА, <напряжение батареи> В. Режим приоритета <UTI/SBU/SOL>:
  в UTI пока есть сеть, нагрузка идёт от сети (байпас, `work_state=4`) и батарея заряжается от сети; при отключении
  инвертор питает дом от батареи (`work_state=2`).
- **Батарея LiFePO4 <N>S, <ёмкость> А·ч**, **BMS JK <модель>**.
- **Сбор данных**: агент `mxg` на ТВ-приставке у инвертора; опрос инвертора по USB (Modbus) и BMS по Bluetooth раз в
  10 с. Wi-Fi приставки может терять пакеты — возможны пропуски данных.

## Файлы

| Файл | Строка | Содержание |
|---|---|---|
| `data-ДЕНЬ.csv` / агрегаты `inverter_*.csv` | 10 с | данные инвертора |
| `bms-ДЕНЬ.csv` / агрегаты `bms_*.csv` | 10 с | данные BMS |
| `events.csv` | событие | журнал агента: `time,kind,notified,text` |
| `daily_summary.csv` | день | сводка по дням |
| `settings.json` | снимок | настройки инвертора (названия, значения) |

В агрегатах `X` — среднее за интервал, `X_min`/`X_max` — минимум/максимум, `n` — число исходных строк
(10-секундных). Интервал без строк в файл не попадает — **пропуск времени = нет данных, а не «ноль»**.

### Инвертор (`data-*`, `inverter_*`)

| Колонка | Ед. | Смысл, достоверность |
|---|---|---|
| work_state | код | 0 включение, 1 самотест, **2 от батареи**, 3 с сетью, **4 от сети (байпас)**, 5 стоп, 6 заряд от сети |
| grid_v | В | напряжение сети; **< 150 В = света нет**. Бывает 160–170 В (слабая сеть вечером) |
| out_v, out_hz | В, Гц | выход инвертора (в байпасе ≈ сеть) |
| batt_v | В | напряжение батареи по инвертору |
| soc_est | % | **грубая оценка по напряжению**, не использовать, если есть BMS |
| load_w, load_pct | Вт, % | нагрузка; в байпасе инвертор может показывать 0 (не мерит) |
| inv_w, grid_w | Вт | мощности инвертора/сети (не сверено с дисплеем) |
| batt_w, batt_a | Вт, А | батарея по инвертору (знак не сверен — опирайтесь на BMS `current`) |
| pv_v, pv_w, chg_a | | солнечный контроллер, панелей нет → 0 |
| bus_v | В | шина DC инвертора (~400 В) |
| temp_a, temp_b, temp_dc | °C | радиатор AC, трансформатор, радиатор DC; «пила» 35–55 °C = циклы вентиляторов |
| temp_chg | °C | радиатор солнечного контроллера |
| err_inv, warn_inv, err_chg, warn_chg | маска | биты ошибок/предупреждений; `err_chg=32` (бит 5) — «PV низкое», норма |
| e_load, e_buy, e_discharge, e_grid_charge, e_charge, e_pv | кВт·ч | **накопительные счётчики** инвертора за всё время; энергия за период = разница |

### BMS (`bms-*`, `bms_*`)

| Колонка | Ед. | Смысл |
|---|---|---|
| soc | % | **настоящий заряд от BMS** (главный показатель) |
| voltage | В | напряжение батареи по BMS (точнее инвертора) |
| current, power | А, Вт | **+ заряд, − разряд** |
| remaining_ah, capacity_ah | А·ч | остаток / полная ёмкость |
| cell_min, cell_max, cell_delta, cell_avg | В | ячейки; разбаланс `cell_delta` норма < 0,02 В, тревога ≥ 0,1 В |
| cell_min_idx, cell_max_idx | № | номер ячейки 1–8 |
| c1…c8 | В | напряжение каждой ячейки |
| temp1, temp2, temp_mos | °C | датчики батареи и силовых ключей |
| balancing, balance_a | код, А | 0 нет, 1 заряд, 2 разряд; ток балансира |
| charge_on, discharge_on | 0/1 | ключи заряда/разряда BMS; 0 = BMS отключила |
| errors | маска | аварии BMS (бит 4 «полностью заряжена» — информационный) |
| cycles, soh | шт, % | циклы, здоровье |

## События (`events.csv`, поле kind)

`grid_lost` / `grid_back` — свет пропал/вернулся (текст содержит длительность; пометка «время по BMS» — момент
восстановлен по току батареи, т.к. связи с инвертором не было) · `batt_down` / `batt_up` — заряд пересёк 10 %-уровень
· `comm_lost` / `comm_back` — связь с инвертором · `usb_reset` — агент перезапустил USB инвертора (см. ниже) ·
`fault_set/clear`, `warn_set/clear` — ошибки/предупреждения инвертора · `bms_*` — BMS (аварии, ключи, разбаланс,
связь) · `info_*` — информационное (ночное «PV низкое») · `setting` — изменение настройки инвертора владельцем.

## Известные особенности (не считать аномалиями без проверки)

- **При возвращении сети USB-чип инвертора может зависнуть** (импульс при переключении на байпас). Агент сбрасывает
  питание USB за 30–40 с (`usb_reset` в событиях) — отсюда короткие пропуски данных инвертора около `grid_back`;
  данные BMS при этом идут.
- После отключения питания приставки часы выставляются по NTP; до этого данные не пишутся.
- Поля PV и солнечного контроллера не информативны, если панелей нет.

## Полезные вопросы для анализа

- Сколько и каких отключений (число, длительность, время суток), сколько заряда батареи тратится за час отключения
  при типичной нагрузке, хватит ли батареи на N часов.
- Глубина разрядов (минимальный SOC), сколько времени батарея стоит полной (100 %) — для LiFePO4 полезно не держать
  постоянно 100 %.
- Разбаланс ячеек и его рост, ячейка-«отстающая» (часто одна и та же `cell_min_idx`).
- Качество сети: просадки `grid_v`, частота, сколько времени сеть ниже 180 В.
- Нагрев инвертора от нагрузки и заряда, частота циклов вентиляторов.
- Энергия: потребление дома за сутки (`e_load`), сколько ушло на зарядку от сети (`e_grid_charge`).
