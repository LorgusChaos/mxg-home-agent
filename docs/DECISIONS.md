# Технические решения и подводные камни

Что выяснилось на реальном железе (Amlogic S905, Android 5.1, ядро 3.14; Must PV18-3224 VPM II; JK-B2A8S20P) и почему
код устроен именно так.

## Платформа и сборка

- **Один статический бинарник Go, `GOOS=linux GOARCH=arm GOARM=7`, `CGO_ENABLED=0`.** Ядро 64-битное, но сборка
  arm64 на Go 1.26+ падает с `SIGILL` в случайный момент: рантайм читает счётчик `cntvct_el0`, а старое ядро не
  открывает его для EL0. 32-битная сборка работает, usbfs из 32-битного процесса — через compat-ioctl.
- **Нет `/etc/resolv.conf`**: DNS берётся из `getprop net.dns*` (свой `net.Resolver`). Для `api.telegram.org` —
  запасные IP и последний удачный адрес, если DNS не ответил (TLS проверяет имя).
- **Нет корневых сертификатов Let's Encrypt и `zoneinfo`**: встроены `x509roots/fallback` и `time/tzdata`; часовой
  пояс — из `persist.sys.timezone`.
- **Нет часов реального времени**: после отключения питания дата 2015-01-01. Агент ставит время по SNTP и до этого
  не пишет данные и не шлёт уведомления; раз в час подправляет часы при расхождении > 2 с.
- `settings` и `svc` на этой прошивке — скрипты без `#!`: вызывать через `sh`.
- busybox 1.22: нет `stat -c` (размер — `wc -c`).

## Связь с инвертором

- **Свой драйвер CH340 через usbfs** (`/dev/bus/usb/BBB/DDD`, ioctl CONTROL/BULK/CLAIMINTERFACE): модуля `ch341`
  в ядре нет. Инициализация и делитель скорости — как в Linux `ch341.c`.
- Протокол — **Modbus RTU 19200 8N1, адрес 4** (Voltronic-команды Q* не отвечают). Карта регистров —
  [must_modbus.md](must_modbus.md).
- **Журнала событий в инверторе через Modbus нет** (развёртка адресов: данные только в известных блоках) — журнал
  ведёт агент (`events.csv`).
- **Запись настроек (функция 6) применяется с задержкой**: эхо приходит сразу, а регистр меняется позже 0,3 с →
  агент перечитывает до 6 с. Только белый список с собственными пределами (диапазоны из открытых карт противоречили
  реальным значениям). Ресурс EEPROM инвертора ограничен — запись только по явной команде владельца.
- **CH340 зависает при возвращении сети**: в момент перехода инвертора на байпас (переключение АВР/реле) чип
  перестаёт отвечать даже на чтение дескриптора (EPROTO). Импульс доходит, вероятно, через адаптер питания приставки,
  включённый в выход инвертора, и USB-кабель. Лечится только снятием питания с порта:
  `/sys/devices/dwc2_X/buspower` 0→1 (Amlogic dwc_otg). Агент делает это сам после 3 неудачных опросов; паузы
  1/2/5/10 мин. Радикально — USB-гальваноразвязка и/или питание приставки от батареи через изолированный DC-DC.
- Если смена сети пришлась на перерыв связи с инвертором, время события берётся по BMS (конец/начало разряда,
  гистерезис −3/−1,5 А).

## Связь с BMS

- Bluetooth приставки работает под Bluedroid в пространстве пользователя, ядерного HCI нет → BLE доступен только
  через Android API → **приложение-мост** (`bmsbridge`, без UI): подключается, подписывается на FFE1, шлёт 0x97/0x96,
  проверенные кадры (300 байт, сумма по модулю 256) пишет в файлы; разбор — в агенте (`internal/jkbms`).
- JK BMS держит **одно** BLE-подключение: пока подключён мост, приложение JK на телефоне не подключится.
- Некоторые JK BMS вещают имя = серийный номер (не «JK…») — адрес задаётся явно (`--es mac`).
- Уровни батареи в уведомлениях — по SOC BMS, если данные свежие (< 60 с); иначе запасная оценка по напряжению.

## ADB и сеть приставки

- **adbd этой прошивки обслуживает одно TCP-соединение и без keepalive**: если сессия оборвалась без FIN, новые
  подключения принимаются, но не читаются (`offline`). Признак — сокет на порту 5555 с непрочитанными данными
  (ESTABLISHED/CLOSE_WAIT) две проверки подряд → `kill -9 adbd` (init поднимает заново). Делает агент; есть и
  отдельный `scripts/adbd_watchdog.sh`.
- **Без монитора Android считает экран выключенным** и включает энергосбережение Wi-Fi (`wl PM 2`), из-за чего
  теряются входящие пакеты. Агент: `wl PM 0` каждые 5 с (Android возвращает ~раз в 45 с),
  `wifi_suspend_optimizations_enabled=0`, `svc power stayon true`.
- Процессы ищутся только точным сравнением `/proc/PID/cmdline` — иначе команда поиска находит сама себя.
- `start.sh` ждёт, пока супервизор поднимется: если вызывающая adb-сессия закроется сразу, adbd убивает
  ещё не отделившийся дочерний процесс.
- Обновление агента — скриптом на самой приставке (`setsid … update.sh`), чтобы обрыв ADB не оставил её без агента.

## Надёжность

- **Приставку никогда не перезагружать автоматически** — только перезапуск сбойной службы (adbd, USB-порт, агент
  через `run.sh`, мост раз в 5 мин).
- Автозапуск — `/system/su.d/90mxg` (SuperSU daemonsu выполняет его при загрузке), агент поднимается без UI-части
  Android.
- События с защитой от дребезга: сеть — 3 опроса подряд, ошибки/ключи BMS — 2 опроса; «тихие» биты (ночное
  «PV низкое», «батарея полностью заряжена») только в журнал.

## Просмотрщик и управление

- Сервер только на `127.0.0.1`, проверка `Host` (от DNS rebinding), POST только с заголовком `X-Mxg` (сторонняя
  страница в браузере не может отправить команду). Системные `confirm()` не используются (во встроенных браузерах
  молча возвращают «Отмена») — подтверждение в строке.
- Команды на приставку — файлами `/data/mxg/cmd/ID.json` (пишутся через `.tmp` + `mv`), со сроком годности 2 мин;
  агент выполняет их в том же потоке, что и опрос (порт не делится).
- Экспорт для ИИ — агрегаты (среднее/мин/макс) вместо сырых 10-секундных строк: ~5 тыс. токенов в сутки при шаге
  10 мин вместо ~1 млн.

## Мост BMS → инвертор (план)

Инвертор принимает данные «умной» батареи только по **CAN** (порт RJ45 BMS: 5 CAN-L, 6 CAN-H, 3/4 GND), программы
меню 37–41 (метод управления по SOC, пороги, поведение при потере связи, номер протокола). План — адаптер USB-CAN
(slcan → cdc_acm) и эмуляция Pylontech CAN из данных JK. Выжимка из инструкции — [inverter_manual_notes.md](inverter_manual_notes.md).
